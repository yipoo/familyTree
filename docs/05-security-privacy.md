# 安全与隐私

## 1. 威胁模型（摘要）

- 普通用户尝试越权读取其他房支或敏感字段。
- 撞库/暴力破解登录；Token 窃取。
- 大文件导入导致 DoS；导出泄露全库。
- 内部管理员滥用导出。

缓解方向：纵深防御、最小权限、审计、限流与告警。

## 2. 认证

- 密码存储：`argon2id` 或 `bcrypt`（足够 cost）。
- JWT：`exp` 短（如 15m）、`aud`/`iss`、仅 HTTPS；Refresh 旋转与复用检测。
- Session：Cookie `HttpOnly` `Secure` `SameSite=Lax`（嵌入场景评估 `None`）。
- MFA：TOTP 优先；恢复码一次性哈希存储。

## 3. 授权模型

### 3.1 RBAC 默认矩阵

角色默认能力在配置中定义；**数据范围**单独声明：

- `scope: global | branch:{rootPersonId} | subtree:{personId}`

### 3.2 字段级策略

示例策略键：`person.contact.phone` — 角色 `member` 为 `deny`，`branch_admin` 为 `allow` 当 `person in scope`。

### 3.3 实现要点

- **查询层过滤**：ORM scope 或显式 WHERE；禁止在控制器里手动拼列表过滤大量 ID 而无索引。
- **403 vs 404**：对外部不可枚举资源可采用 404；内部管理 UI 可用 403 区分。

## 4. 在世人员隐私

- 默认模板：`living_person_strict`：隐藏精确生日、住址、联系方式；仅展示辈分与关系。
- 空间级可配置「族人默认可见级别」。

## 5. 审计日志

必须记录（最低集）：

- 登录成功/失败；MFA 变更。
- 角色与范围变更；邀请接受。
- 人员合并/删除；导入确认应用；导出完成。
- 管理员查看敏感字段（若提供「破冰」功能）。

保留期：不少于法规要求；可归档冷存储。

## 6. 传输与静态安全

- 全站 TLS 1.2+；HSTS。
- 对象存储 bucket 私有；下载链接短时签名。
- 数据库磁盘加密（云厂商）；密钥 KMS。

## 7. 合规注意点（非法律意见）

- 个人信息：收集目的告知、导出权、删除/匿名化请求流程。
- 若含欧盟用户：GDPR 设计点（DPA、跨境、Cookie 同意）。
- 日志中避免明文记录密码与完整 Token。

## 8. 安全开发生命周期

- 依赖漏洞扫描（SCA）；容器镜像扫描。
- PR 安全自检清单：新接口是否鉴权、是否租户隔离、是否可批量拉取。
