# ADR 001：多租户数据隔离策略

- 状态：提议
- 日期：2026-04-15

## 背景

家谱系统以「家族空间」为租户边界，需防止跨租户数据泄露，并兼顾运维成本与查询性能。

## 选项

1. **单库共享 schema + `tenant_id` 列**：应用层与可选 RLS 过滤。
2. **每租户独立 schema**：隔离更强，迁移与连接管理复杂。
3. **每租户独立数据库**：隔离最强，成本高，适合超大客户或合规专有云。

## 决策

采用 **选项 1：单库共享 schema + 强制 `tenant_id`**，并：

- 所有业务表含 `tenant_id` + 索引；查询封装强制带入。
- 可选启用 PostgreSQL RLS 作为纵深防御。
- 若未来出现超大租户，再评估 **选项 3** 的「大客户专库」分支（新 ADR）。

## 后果

- 迁移与备份简单；连接池利用率高。
- 开发必须严格遵守租户过滤，代码审查与静态分析规则需配套。
- 统计与批量任务禁止无 `tenant_id` 的全表扫（除非维护窗口内的全局任务）。
