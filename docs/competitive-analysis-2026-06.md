# 家谱系统竞品调研与产品完善建议（PM 视角，2026-06）

> 与 `gap-analysis-2026-05-05.md` 的区别：那份是「文档承诺 vs 代码实现」的**工程差距**；本份是「我们的产品 vs 整个家谱市场」的**竞品/市场差距**，从产品经理角度拆解功能、体验、效率、商业化四个维度，给出可落地的优先级建议。
>
> 调研方法：网络调研国际四强（Ancestry / MyHeritage / FamilySearch / Geni / WikiTree）+ 国内主流（族谱网 / 族谱录 / 百姓通谱 / 华谱系统 / 修谱王·家谱国际 / 大谱师 / 百家有谱 / 云码宗谱）+ 移动端·小程序 + 2024–2026 AI 趋势，再与本仓库实际能力逐项对照。

---

## 0. 一页结论（TL;DR）

**我们是谁**：一个**工程质量优秀的「修谱工具 + 家族运营平台」**，最接近的对标是大谱师 / 族谱网 / 百家有谱（国内工具型 SaaS），而**不是** Ancestry（历史档案库 + DNA 那套我们不做、也不该做）。

**我们已经很强的地方**：关系树 / 吊线图 / 详细图布局、5 套册谱版式（合编·牒记·欧式·苏式·宝塔）+ 异步 PDF、居住地继承、子树管理员细粒度权限、Excel 导入对账、GEDCOM/CSV/JSON 导出、审计 + 撤销 + 待审提交闭环、邀请码/分享链接/入族申请、多租户 + 发现页、字辈/源流/族规打印字段。**这套"数据建模 + 传统谱式 + 协作权限"在国内工具里属于第一梯队。**

**最痛的 5 个市场空白**（按 ROI 排序）：

| 优先级 | 空白 | 为什么痛 | 我们已有的基础（=改动小） |
|---|---|---|---|
| **P0-①** | **媒体/影像层**（照片/文档/音视频管理，不止一个 avatarUrl） | 所有竞品标配；它是相册成书、纪念馆、AI 修图的**地基**，不做它后面全做不了 | 仅有 `Person.avatarUrl`，**无对象存储、无相册实体** → 这是最大地基缺口 |
| **P0-②** | **二维码采集 / 族人自填** | 国内竞品人人都吹"录入效率"，这是众包录入的杀手锏 | **已有 `PendingSubmission` 审核闭环**，只差一个"对外自填表单 + 二维码"入口，复用现成审核流 |
| **P0-③** | **微信小程序「扫码查阅」只读端** | 中国家族用户活在微信里；没有微信入口 = 没有传播 | 已有 `ShareLink` + `public-url` + 只读分享页，小程序可直接复用数据通道 |
| **P1-①** | **AI 人物传记 / 家族故事生成（中文）** | MyHeritage AI Biographer、Ancestry AI Stories 已是标配；情感留存利器 | **人物结构化数据 + biography 字段齐全**，加一次 LLM 调用即可，改动极小 |
| **P1-②** | **老谱 OCR（繁体竖排识别）导入** | 中文家谱最高价值 AI 能力；对标 FamilySearch 全文检索 | 已有 xlsx 导入对账管线，OCR 产物可复用其 upsert 逻辑；难点在 OCR 模型（外采） |

**一句话**：我们的"骨架"（数据 + 谱式 + 权限）已经很好，缺的是"血肉"（**影像、AI、微信触点、众包录入、情感/社交场景**）——这正是 2025–2026 全行业从"工具"卷向"体验"的方向。

## 1. 市场全景：四类玩家，我们在哪

家谱市场可分四层，商业模式和能力重心完全不同：

| 层 | 代表 | 核心资产 | 变现 | 与我们关系 |
|---|---|---|---|---|
| **国际·档案+DNA 大数据** | Ancestry、MyHeritage | 数百亿历史档案 + 千万级 DNA 库 | 档案订阅 + DNA 试剂盒 | **不对标**（我们没有也不需要档案库/DNA），但其 **AI/体验**值得抄 |
| **国际·协作世界树** | FamilySearch、Geni、WikiTree | 一棵全球共享大树 + 免费档案 | 免费/捐赠/Pro | 协作模型、全文检索 AI 可借鉴 |
| **国内·门户+内容** | 族谱录、百姓通谱网、上图/国图数据库 | 姓氏源流、纪念馆、目录数据 | 增值祭祀/会员 | **寻根/纪念**场景借鉴 |
| **国内·工具型 SaaS（我们在这）** | 族谱网、大谱师、百家有谱、修谱王、云码宗谱、华谱系统 | 录入工具 + 谱式排版 + 印刷 | 免费工具引流 → **印刷**（60–300 元/本）+ 会员（如族谱网 398 元/年）+ 修谱服务 | **直接竞品** |

**我们的定位锚点**：在"国内工具型 SaaS"里，我们的**数据建模严谨度、权限粒度、审计/导出标准化**领先（华谱系统在学术/知识图谱上更强，但产品化体验弱）；我们落后在**影像、AI、微信生态、印刷变现闭环、年轻化可视化、寻根/纪念社交**。

## 2. 竞品拆解（PM 视角的需求拆解）

### 2.1 国际四强 —— 抄什么

| 维度 | Ancestry | MyHeritage | FamilySearch | 给我们的启示 |
|---|---|---|---|---|
| 建谱 | 私有树 + Hints「摇叶子」智能提示 | 私有树 + Smart Match/Record Match（带置信度%） | 单棵共享世界树，"挂靠"而非重建 | **置信度提示 + 主动 hints** 是建谱体验的核心 |
| 档案/检索 | 600 亿档案 + **全文检索**(beta) | 200 亿档案 + **AI Record Finder**(对话式检索) | **Full-Text Search**：AI 识别手写体，把 12 亿张原先检索不到的图像变可搜 | **AI 全文检索/对话式检索**是 2024 最大突破 |
| DNA | AncestryDNA + ThruLines（推断亲缘路径） | Theory of Family Relativity（解释"如何"相关） | 无 DNA | 我们不做 DNA |
| **AI 影像** | Face Match、文档转写、**AI Stories（叙事+配音）** | **Deep Nostalgia→LiveMemory（照片转视频）、In Color 上色、AI Time Machine、AI Biographer** | 手写转写、记录摘要 | **照片修复/上色/动态 + AI 传记**是情感留存王牌 |
| 故事化 | LifeStory 自动时间线+地图、AI Stories 配音 | AI Biographer 维基式传记 | Memories 相册+录音 | **"档案→叙事"**是新战场 |
| 可视化 | 竖/横/扇形图 | 谱系图 + PedigreeMap 地理 | 扇形/世代/肖像图 + 地图 | **扇形图 + 地图视图** |

**国际趋势（2024–2026）**：① 生成式 AI 已是标配；② AI 手写/全文转写是档案突破；③ "档案→自动叙事（含配音）"成留存战场；④ 照片从"动脸"卷到"动整场景视频"；⑤ 对话式研究助手；⑥ 准确性护栏（反幻觉、数据授权）成为新卖点。

### 2.3 移动端 / 小程序模式

- **微信小程序是国内主入口**：名门修谱、云族谱、族谱网认亲、修谱王认亲、新式族谱等都靠小程序做"零门槛建谱 + 扫码查阅 + 二维码采集 + 宗亲社交"。
- **手机即扫描仪**：Ancestry 内置 Photomyne 拍照扫老照片→自动裁切→上色修复；国内对应"老谱拍照 OCR"。
- **语音口述史**：FamilySearch Memories 录 15 分钟先人语音/讲述，自动挂到人物。
- **二维码墓碑/扫码寻亲**：扫墓碑二维码看生平/相册/家谱，联动清明在线祭祀——国内独特品类。
- **小屏可视化**：星系谱、族谱圆（同心圆）是为手机 pan/zoom 设计的替代布局。

## 5. 完善建议

### 5.1 功能完善（按优先级，沿用项目 P0/P1/P2 命名）

> 排序标准：**地基性/解锁性 > 高ROI(高感知×已有80%基础) > 差异化 > 远期生态**。

#### 🟥 P0 —— 地基与高 ROI（建议本季度）

**P0-① 媒体/影像层（对象存储 + 相册实体）**
- *做什么*：接入对象存储（S3/OSS/COS），新增 `Media` 实体（type: PHOTO/DOC/AUDIO/VIDEO，挂到 person/family/marriage/event），人物详情页相册、家族相册、老谱扫描件归档。
- *为什么先做*：这是**地基**——相册成书、纪念馆、AI 修图/动态、二维码墓碑全都依赖它。现在只有一个 `avatarUrl` 字段，等于没有影像层。
- *已有基础*：`Person.avatarUrl` 字段、审计/权限框架可直接复用。
- *规模*：中（存储接入 + 1 个实体 + 上传组件 + 详情页相册区）。

**P0-② 二维码采集 / 族人自填表单**
- *做什么*：管理员对某人物/某分支生成"采集链接 + 小程序码/二维码"，族人无需登录即可补全自己及直系信息（姓名/生卒/照片/婚配/子女），提交后进入**现有 `PendingSubmission` 审核流**，管理员一键并入。
- *为什么先做*：国内竞品人人吹"录入效率"，二维码众包是杀手锏；**我们已有审核闭环，只差一个对外入口**，是典型"高感知 × 已有 80% 基础"。
- *已有基础*：`PendingSubmission` + `submissions.ts` diff/describe + 审核 UI 全现成；`ShareLink` 的 token 机制可复用。
- *规模*：低-中。

**P0-③ 微信小程序「扫码查阅」只读端（最小可用）**
- *做什么*：先做只读小程序壳——扫码/搜索看关系树、人物详情、相册、吊线图；登录态打通后逐步加"我的家族""二维码采集"。
- *为什么先做*：中国家族用户活在微信里，没有微信入口=没有自然传播；只读端能立刻把"分享"变成"裂变"。
- *已有基础*：`ShareLink` + `lib/api/public-url.ts` + 只读分享页 + `/graph` `/lineage-chart` JSON API 都现成，小程序直接消费。
- *规模*：中（新端，但后端零改动起步）。

#### 🟧 P1 —— 差异化与情感留存（下季度）

**P1-① AI 人物传记 / 家族故事生成（中文）** — 一键把人物结构化数据（生卒/婚配/子女/迁徙/居住地）+ 字辈/源流上下文，生成中文传记/小传，支持配音（对标 Ancestry AI Stories）。**数据现成、加一次 LLM 调用**，ROI 极高。反幻觉护栏：只用谱内事实，不编造。
**P1-② 老谱 OCR 导入（繁体竖排）** — 拍照/上传老谱页 → 外采 OCR（云聪/千百OCR/自训）识别繁体竖排 → 结构化为人物/世系 → 进入**现有 xlsx 导入对账管线**的 upsert。中文家谱最高价值 AI。
**P1-③ 五服图** — 复用 `lib/services/kinship.ts`（已算 kin5 五代）渲染传统五服丧服图。传统修谱刚需、**算法已有**、改动小。
**P1-④ 编辑期智能纠错** — 录入/编辑时实时提示：重名预警、生卒年份矛盾、辈分/世代冲突、父子年龄倒挂。复用 xlsx-import 的 issues 校验逻辑下沉为共享校验器。
**P1-⑤ 族谱圆 / 同心圆可视化** — 在 `tree-layout.ts` 之外加一套径向布局（同代同环、字辈为环），适配手机 + 拉新年轻用户。
**P1-⑥ 谱序/凡例/源流/像赞/艺文 完整编辑 + 样本库** — 把现有 3 个打印字段扩成完整的"谱书前后页"编辑器，配模板/样本库（竞品都有"样本库"降门槛）。

#### 🟨 P2 —— 生态与远期

- **P2-① 印刷成书变现闭环**：PDF → 对接印厂（宣纸线装/精装），下单/物流/分成。这是国内主要变现路径。
- **P2-② 网上纪念馆 / 祭祀 + 二维码墓碑**：人物纪念页 + 清明季在线祭拜 + 墓碑二维码（扫码看生平/相册/家谱）。情感留存 + 季节性变现。
- **P2-③ 老照片 AI 修复/上色/动态**：外采 API，相册一键修复/上色/转视频（LiveMemory 模式），病毒传播。
- **P2-④ 跨族同宗匹配 / 寻根**：基于姓氏+始祖+字辈+迁徙，在公开家族间做候选匹配（从发现页升级）。网络效应远期护城河。
- **P2-⑤ 对话式家谱问答**：RAG over 本族数据（"谁是我曾祖的兄弟？"）。
- **P2-⑥（高风险，可选）AI 数字人/纪念对话**：情感拉力强、变现清晰，但**必须**逝者肖像/声音授权 + 算法备案 + 伦理框架，建议观望或仅做合规版。

### 5.2 体验完善（Experience）

1. **移动端树谱导航重做**：当前关系树为宽幅左右布局，手机体验差。引入族谱圆/径向布局 + "先定位到我，再看家族"的 kin5 聚焦默认视图。
2. **拍照即录入**：手机端"拍老谱/拍老照片"直接进 OCR/相册，消灭手动转录（对标 Photomyne）。
3. **引导式建谱向导**：空族首次进入给"3 步建谱"向导（建始祖→加配偶/子女→设字辈），降低冷启动门槛（竞品"会打字就会修谱"卖点）。
4. **录入实时校验反馈**：把 P1-④ 的纠错做成行内即时提示，而非提交后报错。
5. **一键分享到微信**：生成小程序码/分享卡片（人物名片、家族邀请、采集二维码），把每一次分享变成裂变。
6. **大族性能体感**：万人级关系树按视口/分支分块加载（gap-analysis 已提性能项），首屏不卡。

### 5.3 效率完善（Efficiency）

1. **二维码众包采集**（=P0-②）：把"管理员一个人录全族"变成"每人填自己"，这是录入效率的根本性提升。
2. **OCR 替代手工转录**（=P1-②）：老谱从"逐行敲"变"拍照识别 + 校对"。
3. **AI 辅助写谱文**（=P1-①）：传记/小传/谱序从"提笔难"变"一键生成 + 润色"。
4. **批量操作**：批量改字辈、批量设支系、批量补居住地（继承可一键应用）。
5. **模板/样本库**：谱序/凡例/源流/族规提供可套用样本（竞品标配，降门槛）。
6. **导入对账增强**：现有单 sheet → 三 sheet（人物/关系/迁徙），减少二次整理（gap-analysis P1-E 已列）。

### 5.4 商业化建议（PM 视角）

国内工具型家谱的成熟变现是"**免费工具引流 → 印刷/服务/会员/AI 增值**"四条线：

| 变现线 | 做法 | 对标 | 我们就绪度 |
|---|---|---|---|
| **印刷成书** | PDF → 宣纸线装/精装下单（60–300 元/本） | 百家有谱/修谱王 | 近（已有册谱 PDF，缺印厂对接）|
| **会员订阅** | 存储扩容 / 高级版式 / AI 功能 / 去水印 | 族谱网 398 元/年 | 缺会员体系 |
| **AI 增值** | AI 传记配音、照片修复/动态、OCR 按量 | MyHeritage Complete | 缺（先做 P1-①/P1-②） |
| **修谱服务** | 代录入/代修复/代撰谱文（人工+AI） | 修谱王/百家有谱 | 缺（可外包/众包）|

**建议节奏**：先用 P0/P1 把"影像+AI+微信"做厚（提留存与传播），再开"印刷 + 会员 + AI 增值"三条变现线；AI 数字人/纪念馆作为高情感场景在合规后接入。

## 6. 建议路线图（季度视角）

```
本季度 (P0 · 地基与传播)
 ├─ 媒体/影像层（对象存储 + 相册/文档/音视频）        ← 解锁后续一切影像/AI
 ├─ 二维码采集 / 族人自填（复用 PendingSubmission）    ← 录入效率质变
 └─ 微信小程序「扫码查阅」只读端                        ← 打开传播渠道

下季度 (P1 · 差异化与留存)
 ├─ AI 人物传记/故事（中文，结构化数据→LLM）
 ├─ 老谱 OCR 导入（繁体竖排，外采→现有对账管线）
 ├─ 五服图（复用 kinship.ts）
 ├─ 编辑期智能纠错（复用导入校验）
 ├─ 族谱圆/同心圆可视化
 └─ 谱序/像赞/艺文完整编辑 + 样本库

第三季度+ (P2 · 生态与变现)
 ├─ 印刷成书闭环（对接印厂）+ 会员体系 + AI 增值计费
 ├─ 网上纪念馆/祭祀 + 二维码墓碑（清明季）
 ├─ 老照片 AI 修复/上色/动态
 ├─ 跨族同宗匹配/寻根（发现页升级）
 └─ 对话式家谱问答；（合规后）AI 数字人
```

**指导原则**：① 先建地基（影像层）再长血肉；② 优先"已有 80% 基础"的高 ROI 项（二维码采集、AI 传记、五服图）；③ 微信生态决定传播天花板，尽早进入；④ 守住我们已领先的"数据/权限/审计/标准导出"基本盘，不要为追功能牺牲工程质量。
